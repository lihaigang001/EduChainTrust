# EduChainTrust v1.12.0 local user manual

Install Python 3.11+ and `python -m pip install -e '.[all]'`. Run `python examples/university_demo.py` for an entirely synthetic, local credential and revocation walkthrough.

Provision once with `python tools/generate_local_config.py --issuer University-A`. Record the randomly generated issuer/verifier/admin `X-API-Key` strings from stdout and keep `local-config/` private. Set `EDUCHAINTRUST_CONFIG` to the absolute path of `local-config/config.json`; then run `uvicorn api.main:app --host 127.0.0.1 --port 8000`. The API refuses to start without tokens and a trusted issuer key. On POSIX it also refuses configuration or issuer private-key files readable by group or others. After copying or editing them, use `chmod 700 local-config` and `chmod 600 local-config/config.json local-config/issuer-key.pem` (adjust the key path if rotated). On POSIX, use regular files for the configuration and PEM paths; each symlinked path component and group/other writable parent directory is refused, except a root-owned sticky temporary directory. All parent directories and the file must be owned by root or the service UID, or by an operator UID explicitly trusted through `EDUCHAINTRUST_TRUSTED_CONFIG_UID`. For Windows, review the actual file ACLs separately; POSIX mode and final-symlink enforcement do not apply. `EDUCHAINTRUST_DB` optionally sets a persistent SQLite file path.

Endpoints: `/v1/identities` and `/v1/credentials` require the issuer token; `/v1/evidence/anchor` requires a structurally valid credential signed by that issuer's current active key; `/v1/evidence/revoke` requires the owning issuer or administrator. `/v1/credentials/verify`, `/v1/evidence/{tx_hash}/status`, and `/v1/analytics/evidence-score` require an authenticated role. Root and health endpoints are public. All protected requests carry `X-API-Key`.

`/v1/credentials/verify` returns independent booleans for structure, trusted issuer, signature, validity time, digest, and issuer/anchor match, plus active/revoked/unknown status. The aggregate `verified` value is true only when every check passes and evidence is active. A revoked record still has matching content, reported separately from its inactive status. Duplicate anchoring of the same signed credential is rejected. A legacy v1.2.4 SQLite row has no issuer attribution and cannot pass aggregate trusted verification after automatic schema migration.

The dashboard (`streamlit run dashboard/app.py --server.address=127.0.0.1`) is a separate session-local demonstration with ephemeral keys and an in-memory ledger. It is not connected to the API or an actual university. This release stores only digest and issuer/lifecycle metadata in SQLite but handles full credential claims in memory and API requests. Use synthetic data only.

An issuer can set `valid_until` in the credential issuance request to a future timezone-aware ISO 8601 timestamp. The returned signed credential contains `validUntil`; verification reports `time_valid=false` after it expires. Keep issuer private keys in local configuration files outside the release archive. A generated issuer entry has `active_method` and `keys` such as `{"active_method":"urn:educhaintrust:example:key-2","keys":{"urn:educhaintrust:example:key-1":{"public_key_file":"old.pub"},"urn:educhaintrust:example:key-2":{"private_key_file":"issuer-key-2.pem"}}}`. Use a distinct method for the new key, anchor all credentials that need old-key evidence before switching, retain a public-only old key to verify those already anchored credentials, and change `active_method` to the new method before restarting the API. New anchors under the old method return HTTP 409 after rotation, even for valid signatures. Pending old-key credentials must be reissued under the active method. Delete an old method only when old anchored signatures should cease to be trusted. Back up the configuration securely before editing. The previous one-key JSON schema still loads. This manual procedure does not automate institutional key custody or rotation.

Run tests with `python -m pytest -q -W error::ResourceWarning --cov=educhaintrust --cov=api --cov-fail-under=85` and regenerate the signed workflow benchmark with `python benchmark/run_campaign.py --n 100 --runs 3 --repeats-per-run 10`. `benchmark/README.md` documents timing scope. Back up an existing SQLite file before a legacy migration. The migration serializes concurrent startup, while schema compatibility and recovery still require operational checks. Docker Compose requires local configuration created in the repository root; for host-user-owned files on POSIX run `EDUCHAINTRUST_TRUSTED_CONFIG_UID=$(id -u) docker compose up --build`. It binds ports to loopback and persists the SQLite file in a named volume.

Docker's `.dockerignore` excludes provisioned keys and local data from the build context; the Dockerfile explicitly copies only application and packaging files. The Compose service mounts `local-config/` read-only at runtime. Run the Compose smoke test on a Docker-capable machine before relying on container behavior.


## Legacy data and migration
Back up the SQLite file before opening it with the newer version. New API evidence has an issuer/credential ID unique index and strict proof encoding. The system checks equivalent signatures against historical hashes. Legacy rows retain NULL credential IDs; hashes cannot reconstruct those IDs. An altered or re-signed old credential with the same ID may not match a legacy digest. Historical noncanonical proof values are accepted only for the exact matching recorded historical bytes; direct store callers must provide identity and legacy digest policy themselves. No production migration or recovery validation is claimed.
